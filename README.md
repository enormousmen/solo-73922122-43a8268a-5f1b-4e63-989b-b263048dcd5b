# 接口延迟告警 · 规则换版台

Flask + SQLite 的接口延迟告警服务，支持在告警持续期间**试算并切换规则版本**，切换时直接接管最新样本状态、不重扫历史。

## 规则语义

- 样本耗时 **严格大于** `threshold_ms` 才算一次超限（等于阈值不算）。
- 连续超限达到 `consecutive` 次才产生**一条**告警；告警期间继续超限不重复告警。
- 任意**一条**未超限样本立即清零计数并恢复（若在告警中，同时产生一条恢复）。
- 每次告警对应一个 `alert_episode`（断连），记录起始/结束样本与耗时，告警和恢复事件通过 `episode_id` 关联。

默认规则 `500ms × 3`，可在页面上试算新版本。

## 换版流程（核心保证）

1. **试算**：对**当前保留的样本**做一次回放，得到预计告警/恢复与末态。结果写入 `trial_events`，标为暂扣，**不会**出现在已发记录 `alert_events` 里。
2. **并行观察**：试算挂起期间仍可正常上报。旧规则继续对外告警；新规则在同一事务里对每条新样本做**影子计算**，不产生对外事件。页面上的“暂扣告警/恢复”就是影子结果。
3. **启用**：直接把影子状态接管为运行时状态（O(1)，`catch_up_samples` 正常为 0，不重扫历史）：
   - 启用前后**都在告警** → 沿用原告警（同一 `episode_id`），不补发事件；
   - 启用前告警、启用后正常 → 补记一条 `recovery`（`cause=activation`），关闭原断连；
   - 启用前正常、启用后告警 → 补记一条 `alert`（`cause=activation`）；
   - 都不告警 → 不产生事件。
   - 试算期间暂扣的预览/影子事件在启用时丢弃，**只有状态变化本身**会记一条。
4. **取消**：新规则置为 `cancelled`，原规则继续生效，告警状态不变；已发记录可查，规则历史里能看到这条被取消的版本。

## 启动

```bash
docker compose up --build -d
# 打开 http://localhost:8000
```

数据持久化在命名卷 `alert-data`（容器内 `/data/alerts.db`），可通过环境变量 `PORT`、`RETENTION` 覆盖端口与样本保留条数（默认 100000）。

停止：`docker compose down`（保留数据）；`docker compose down -v` 连数据一起删。

## 页面演示脚本

1. 打开页面，点击 **灌入演示流量**（每轮 120/450/820/900/950/300，默认 3 连超限，可看到告警→恢复）。
2. 在 **试算新规则** 里填阈值/连续次数，点 **试算并暂扣**：看回放统计和“暂扣的试算事件”。
3. 试算挂起时继续用 **上报一条** 或 **批量序列** 上报超限样本：顶部仍是旧版本且在告警，试算区的影子计数同步增长，已发记录不变。
4. 点 **启用新规则**：弹出确认后，观察“沿用原告警 / 补记告警 / 补记恢复”的提示，以及记录表里 `原因=换版补记` 的那一条（只在状态变化时才有）。
5. 再试算一版，点 **取消试算**：版本历史里出现“已取消”，当前规则与告警状态保持不变。
6. **清空演示数据** 可重置全部样本/记录并恢复默认规则。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/samples` | 上报一条或多条：`{"duration_ms": 120}` 或 `{"samples":[...]}`（单次 ≤1000） |
| POST | `/api/samples/seq` | 批量：`{"values":[120,480,760]}` |
| GET | `/api/status` | 当前规则、运行状态、样本数、试算概览 |
| GET | `/api/events?limit&offset&kind` | 已发告警/恢复记录（分页） |
| GET | `/api/rules` | 规则版本历史 |
| GET | `/api/samples?limit` | 最近样本 |
| POST | `/api/trials` | 试算并暂扣：`{"threshold_ms":800,"consecutive":2}` |
| GET | `/api/trials/<id>/events` | 某试算版本的暂扣事件 |
| POST | `/api/trials/<id>/activate` | 启用 |
| POST | `/api/trials/<id>/cancel` | 取消 |
| POST | `/api/demo/seed` | 灌入演示流量 |
| POST | `/api/demo/reset` | 清空演示数据（不可撤销） |
| GET | `/healthz` | 健康检查 |

同一时间只允许一个待启用试算（第二个返回 409）。

## 设计取舍与已知限制

- **单机 SQLite**：写入串行，适合单实例；多实例部署需要改成外部数据库或单写者。
- **试算回放读快照**：回放不在写锁内，避免 10 万条阻塞上报；快照之后、落库之前上报的样本会在落库时按游标增量补齐（已测）。
- **保留策略按样本条数**：只保留最近 10 万条样本，告警/恢复记录与断连记录**不随样本删除**。
- **启用时的补记只用最新样本**：若规则在“最新样本那一点”上状态与旧规则一致则沿用，不做逐条历史对账——这是“不重扫历史”这一要求的直接结果。
- **未做鉴权**：演示/内网使用；对外暴露前需加认证与 CSRF 防护。
- **本环境无 Docker**：已按镜像布局（`/data` 卷、gunicorn 2 worker × 4 thread、容器同款 HEALTHCHECK 命令）实跑验证，但 `docker compose up` 本身未在此环境执行。
